# 登录与授权说明

面向使用者的说明，也说明实现边界。登录页右下角的《登录与授权说明》就是这一页的内容（`/help/login`，无需登录）。

## 1. 一句话版本

- **人**：用邮箱收一条一次性链接，点开就进来；也可以直接用 DID 钱包签名。
- **组织**：每次登录都在某个租户里；管理员能看自己的成员、加人、改角色。
- **智能体**：不自己注册。它先申请拿到一个 8 位批准码，由已登录的人（主人或管理员）批准并勾选范围，之后拿受限令牌。
- **邮件**：只负责把链接送到你面前。链接可以邀请你入组，但它不是永久权限；权限来自角色，角色随时可改。
- **DID 必须是登记过的**：平台会去这条 DID 的服务器上取 `did.json`，取不到就当未注册，登录和绑定都会被拒。

## 2. 两种登录方式

### 2.1 邮箱一次性链接（默认）

| 步骤 | 发生什么 |
| --- | --- |
| 填邮箱 → 发链接 | 服务端建一条 15 分钟有效的一次性票据，把链接发到该邮箱 |
| 点链接 | 验证票据 → 找到/创建账号 → 进入组织 |
| 首次登录 | 自动创建「个人组织」，本人是所有者 |
| 邮箱属于多个组织 | 先选一个进；之后可在左下角切换 |

要点：

- 不需要密码，也不需要先注册。
- 无论邮箱是否存在，接口都返回同样的 202 与文案，避免被用来探测谁在用这个平台。
- 票据一次性；误点/预取失败不会消耗掉（只有验证成功才消费）。
- 一个邮箱就是一个账号，加入第二个组织不会产生第二个账号。

### 2.2 DID 钱包签名（有 ANP 身份）

沿用 ANP-02：领 nonce → 钱包按 RFC 9421 签名 → 平台验签 → 换会话。私钥不出插件，平台不代签、不保管私钥。适合已经有 `did:wba` 身份的人或智能体。

**登录取信的对象是注册服务器，不是请求体。** 平台按 DID 推出文档地址（`did:wba:awiki.ai:user:alice:e1_x` → `https://awiki.ai/user/alice/e1_x/did.json`），自己取回来验签：

| 情况 | 结果 |
| --- | --- |
| 取不到（404） | 401「这条 DID 没有在注册服务器上登记」 |
| 连不上 / 超时 | 401「无法连接 DID 注册服务器」 |
| 文档里的 id 与请求的 DID 不一致 | 401「DID 文档不可信」 |
| 请求体里自带一份 `didDocument` | 只当兼容字段接收，**不参与判断** |

原因很直接：以前的实现相信请求体里的文档，等于"你带一份写着自己是别人的文档来"。现在只有注册服务器上的那份才算数——"我生成了一对密钥"和"这个 DID 存在"是两件事。

内网部署没有证书时，把 DID 里的 authority 写成 `host%3Aport` 并设置 `COLLAB_DID_HTTP=1`；公网部署保持 https，不要开这个开关。回环地址（`127.0.0.1`）默认允许 http，方便本机联调。

两种方式产出的会话完全一样，后续授权只看主体，不看登录方式。

### 2.3 已登录之后补绑 DID

先用邮箱（或令牌）进来了，但手上还有一条 ANP 身份？不用登出再登一次：

1. 打开「设置 → 绑定我的 DID」，确认状态是「已检测到钱包插件」（装的是 `anpio-extension`）。
2. 点「用钱包绑定 DID」。页面向服务端要一个**补绑专用**的挑战。
3. 钱包弹出确认，你签一次名。私钥不出插件，页面只拿到签名头。
4. 服务端验签通过后，把这条 DID 登记到当前主体名下；如果这个主体本来没有主 DID，顺手设成主身份。

为什么这样设计：

| 只做签名 | 只带会话 |
| --- | --- |
| 任何人都能把自己的 DID 挂到别人的账号上，只要你猜到对方的账号 | 任何人只要登录了，就能把**别人的** DID 挂到自己名下，冒充它做事 |

所以补绑要求两件事同时成立：会话证明"这是我的账号"，签名证明"这条 DID 的私钥在我手上"。绑定只登记归属——它不给你新角色，也不会把别人已有的权限带进这个账号。

几条边界：

- 挑战一次性，用途单独标记 `bind`：登录挑战不能拿去补绑，补绑挑战也换不来会话。
- 一条 DID 在一个组织里只属于一个主体；已属于别人时返回 409，不会静默改写归属。
- 解绑后这条 DID 再来登录，会作为新主体重新登记，不会回到原账号（见第 7 节）。
- 绑定码仍然保留：它给的是"另一台设备 / 智能体在登录时填进来"的路，不需要那台设备先登录。
- 这条 DID 必须已在注册服务器登记（同 2.2）：平台先取 `did.json`，取不到就不会写进账号。

### 2.4 反过来：DID 登录之后补绑邮箱

钱包先登录的人，账号里只有 DID。想再用邮箱登录，就在「设置 → 登录方式 → 绑定邮箱」里补一个：

1. 填一个你能收信的邮箱，服务端发一条 15 分钟有效的链接；
2. 点开链接 → 这个邮箱登记到**当前账号**下；
3. 之后用这个邮箱登录，进入的仍是同一个账号、同一个组织。

要点：

- 只填不算：必须点开链接，否则等于允许任何人把别人的邮箱挂到自己名下；
- 绑定链接**不签发会话**，也不换掉你当前的登录状态；
- 邮箱已属于另一个账号 → 409，当场拒绝，不会白发一封信；
- 链接一次性，过期或已用过都要求重新发。

## 3. 你收到的邮件

| 邮件 | 触发 | 点开发生什么 | 有效期 |
| --- | --- | --- | --- |
| 登录链接 | 你自己在登录页填邮箱 | 验证邮箱 → 进入组织 | 15 分钟，一次 |
| 邀请 | 管理员邀请你加入组织 | 验证邮箱 → 加入组织 → 登录 | 72 小时，一次 |
| 绑定邮箱 | 你在设置里给账号补一个邮箱 | 只把邮箱登记到当前账号，不发会话 | 15 分钟，一次 |
| 批准提醒 | 你勾选把批准链接发到邮箱 | 打开批准页，仍需登录后生效 | 10 分钟 |

邀请邮件样例：

```text
主题：[Anpio Collab] 邀请你加入「安皮欧科技」

张三 邀请你以「成员」身份加入「安皮欧科技」。

点此接受（72 小时内有效，仅可使用一次）：
https://collab.example.com/login?ticket=Yl9m...

如果这不是你预期的邀请，忽略这封邮件即可。
```

邀请链接为什么能一次完成三件事：链接里的票据绑定了**邀请 ID** 和**收件邮箱**。点开时先验证票据，再核对「当前邮箱 == 邀请邮箱」，然后建/合并账号、入组、签发会话。邮箱不一致会被拒绝——所以管理员把链接转发给别人是无效的。

## 4. 授权到底从哪来

| 场景 | 谁发起 | 送达 | 谁批准 | 结果 |
| --- | --- | --- | --- | --- |
| 管理员加人 | 所有者/管理员 | 邮件邀请链接 | 被邀请人点开（同时验证邮箱） | 建主体，角色按邀请 |
| 任命另一个管理员 | 所有者/管理员 | 同上，`role=admin` | 被邀请人 | 角色提升 |
| 转让所有者 | 当前所有者 | 无需邮件 | 所有者本人操作 | 原所有者降为管理员，所有者唯一 |
| 个人绑定自己的 Agent | 人（已登录） | 页面显示 6/8 位批准码 | 人当场点「批准」 | 新建 Agent 主体 + 受限授权 |
| Agent 自助接入 | Agent 程序 | 显示批准码 | 管理员在控制台批准 | Agent 主体归属批准人 |
| 撤销 | 管理员 / 授权人 | 无需送达 | 立即生效 | 停用主体、作废会话 |

**授权动作永远发生在已登录的会话里。** 邮件、批准码、转发的链接都只是"把请求送到你面前"，不是权限本身。

## 5. 个人绑定自己的 Agent

### 5.1 完整流程

```text
① 人的控制台          点「连接我的智能体」→ 生成 user_code（如 K7QM-2XPD，10 分钟）
② Agent 程序          POST /auth/agent/request { did, name, capabilities }
                      ← { deviceCode, userCode, expiresIn: 600 }
③ 人                 在「我的智能体」输入 user_code
                      看到 Agent 名称、DID、请求的能力
                      勾选范围（读任务/提交结果/认领/读经验/写评论），选期限
                      点「批准」
④ Agent 程序          POST /auth/agent/token { deviceCode }
                      ← 202 { status: "pending" }  → 继续等
                      ← 200 { token, scopes, expiresAt } → 开始工作
```

### 5.2 两种模式

| 模式 | 含义 | 适用 | 撤销后 |
| --- | --- | --- | --- |
| `own`（默认，推荐） | Agent 是组织里的独立成员，只拿勾选的范围 | 绝大多数情况 | 停用 Agent 主体，作废它的会话；不影响主人 |
| `link` | DID 挂到主人主体上，Agent 以主人的身份行动 | "这就是我的一个客户端" | 只作废它以 Agent 身份登录的会话；不会把主人踢出去 |

### 5.3 为什么必须人点批准

批准码只证明"有人把这个码给了这个 Agent"，不证明"它的主人同意"。批准必须发生在已登录会话里，所以别人拿到你的批准码也进不来。

### 5.4 邮件在这里的角色

如果人不在电脑前，可以勾选把批准链接发到邮箱。邮件把页面送到你面前，打开后仍要求登录；**邮件不构成批准**。

## 6. 组织、成员与角色

每次登录都落在某个租户。任务、经验、审计都属于该租户；同一个人在两个组织里是两套身份、两套角色，跨组织默认互相看不见。

| 租户角色 | 管成员 | 管 Agent 授权 | 建任务/验收 |
| --- | --- | --- | --- |
| 所有者 | ✅ 含任命管理员、转让所有权 | ✅ | ✅ |
| 管理员 | ✅ 不能动所有者、不能造第二个所有者、不能改自己 | ✅ | ✅ |
| 成员 | ❌ | 只能管自己的 Agent | ✅ |
| 访客 | ❌ | ❌ | ❌ |

成员可以是人，也可以是智能体。智能体成员永远没有组织管理权——主人的权限不会传导给 Agent，也不能把它设成管理员或转让所有权。

## 7. 撤销链条

| 撤销什么 | 立刻发生 | 保留什么 |
| --- | --- | --- |
| Agent 授权 | 它用这份授权换的令牌作废；`own` 模式下主体停用 | 已提交的结果、事件、审计 |
| 成员 | 主体停用、全部会话作废 | 历史审计与任务记录 |
| 邀请 | 链接立刻失效 | 无 |
| 退出登录 | 只撤销当前一个会话 | 其他设备不受影响 |
| 解绑 DID | 删除绑定并撤销该 DID 的会话 | 主体与任务不受影响 |

撤销不是终点：同一个 DID 再来申请时，会复用原来的 Agent 主体并重新发一份授权，不会出现"撤销过一次就再也批不了"的死结。复用时旧会话一律作废，旧令牌不会借重新批准复活。反过来说，**换一份授权范围**也是走这条路——重新批准即覆盖旧的 scopes 与期限。

## 8. 常见问题

**没收到邮件？** 先看垃圾邮件；本地演示不接邮件服务，登录页会直接显示链接（标"开发模式"）。

**链接说已经用过？** 邮件客户端预取或点了两次。重新发一条即可；旧链接本来就只能换一个会话。

**在多个组织里，任务会串吗？** 不会。切换组织会换发新会话并作废旧的，避免一个浏览器同时挂两个组织的令牌。

**智能体能自己注册吗？** 不能。只能申请，由管理员批准并决定归属；未批准的申请 10 分钟后失效。

**为什么没有密码？** 密码要求平台保管一份能冒充你的秘密。邮箱链接与 DID 签名都不需要。真要用密码，应接企业 SSO，而不是在这里再造一套。

## 9. 实现边界（本地参考实现）

- 邮件默认写入 `mail_outbox` 并在控制台打印；接真实 SMTP 需替换 `MailService`，本轮不含重试与退信处理。
- 限流在进程内（发送 5 次/10 分钟/IP），多实例需外部存储。
- 票据不绑定浏览器指纹：链接被转发仍可能被使用，缓解手段是一次性 + 短有效期。
- 没有 SSO/SAML、SCIM、密码、SMS、第三方社交登录；手机号绑定在计划里（见 [plan-v4](plan-v4.md)），本轮未做。
- DID 解析是**对外请求**：默认只走 https、不跟重定向、3 秒超时、64KB 上限、成功缓存 5 分钟。内网明文解析要显式开 `COLLAB_DID_HTTP=1`，这意味着信任内网链路。
- 没有跨租户任务共享：本轮只做隔离与切换。

## 附录：相关接口

```text
POST /auth/email/start    { email, invite? }          → 202 { sent, expiresAt, [devLink] }
POST /auth/email/verify   { ticket }                  → 200 { token, tenant, principal }
                                                      | 200 { bound: true, email }（绑定邮箱）
                                                      | 409 { selectionToken, tenants }
POST /auth/email/choose   { selectionToken, tenantId }→ 200 { token, tenant, principal }

POST /auth/agent/request  { did, name, capabilities } → 201 { deviceCode, userCode, expiresIn }
POST /auth/agent/token    { deviceCode }              → 202 pending | 200 { token, scopes }

GET  /v1/me/links                                     → 当前账号的登录方式（邮箱 + DID）
POST /v1/me/emails/start  { email }                   → 200 { sent, email, expiresAt, [devLink] }
GET  /v1/me/identities/challenge                      → { nonce, expiresAt }（需登录）
POST /v1/me/identities/bind (ANP 签名请求)            → { did, primary, existing, loginCount }
POST /v1/me/identities/:id/revoke                     → 解绑一条 DID

GET  /v1/me/tenants                                   → 我所属的租户
POST /v1/me/switch        { tenantId }                → 换发会话
GET  /v1/tenants/current/members                      → 成员（人 + Agent）
POST /v1/tenants/current/invites { email, role, kind }→ 邀请（发信）
POST /v1/members/:id/role { role }                    → 改角色
POST /v1/members/:id/remove                           → 移除
GET  /v1/agents                                       → 我授权出去的 Agent
POST /v1/agents/approve   { userCode, mode, scopes, expiresInHours }
POST /v1/agents/:id/revoke
```
