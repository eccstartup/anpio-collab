# 本地原型运行与恢复

本说明仅适用于单机开发，不能作为生产部署方案。服务固定监听回环地址，应用进程、数据库及访问令牌由本机用户保护。生产仍需要企业身份、正式密钥管理、加密传输、隔离、审计、PostgreSQL、备份策略和独立安全评估。

## 初始化与授权

首次启动前在终端设置高熵 `COLLAB_BOOTSTRAP_TOKEN`，数据库创建后即使修改环境变量也不会更新现有令牌；不要把令牌放进 Git、命令历史、聊天或任务内容。管理员通过 `POST /v1/principals` 为每个 Agent 登记不同的随机令牌；实际 Agent 只获得自己需要的身份。停用主体立即拒绝其后续请求；已有已提交结果和审计保留。

`COLLAB_DB` 默认是当前目录下的 `collab-ts.sqlite3`；同时保存 `-wal` 和 `-shm` 是 SQLite 正常运行的一部分。不要在服务运行期间单独复制数据库文件作为备份。

## 一致性备份和恢复演练

```sh
node platform/backup.ts collab-ts.sqlite3 /secure/location/collab-backup.sqlite3
```

目标必须不存在。命令先检查源数据库、通过 SQLite `VACUUM INTO` 创建一致性快照，并检查备份完整性。备份含任务、令牌哈希、审计和知识，须按企业数据政策保护；本工具不执行加密、异地传输或保留管理。

恢复演练应在隔离位置对备份副本进行：设置 `COLLAB_DB` 指向该副本，启动本地服务并使用原有授权令牌核对任务、事件、经验引用和主体撤权。不要将测试实例同时指向生产数据库。通过演练后，由运维按批准的停机和恢复流程操作；恢复旧备份可能回滚近期任务及撤权，必须先与外部权威身份、事件和业务系统核对。当前原型没有防回滚机制，不能保证旧备份恢复后撤权仍有效。
