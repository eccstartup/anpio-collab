登录与授权说明

这页讲清楚三件事：你怎么进来、你为什么会收到一封邮件、以及你的智能体凭什么替你做事。 不需要登录也能看。

两种登录方式 邀请邮件 智能体怎么进团队 组织与角色 撤销 常见问题

一、两种登录方式，选一个就行

方式一：邮箱一次性链接（人的默认方式）

  1. 在登录页填工作邮箱，点「发登录链接」。
  2. 去邮箱点开那封邮件里的链接。链接 15 分钟内有效，只能用一次。
  3. 点开就进来了，不需要密码，也不需要先注册。

第一次登录会自动给你建一个「个人组织」，你是这个组织的所有者。之后别人邀请你， 或者你自己建组织，都不会再有第二个账号——一个邮箱就是一个账号。

如果你的邮箱同时属于几个组织，点开链接后会让你选一个进；进去之后可以在左下角随时切换。

方式二：DID 钱包签名（已有 ANP 身份）

  1. 确认浏览器装了 ANP 钱包插件并已解锁。
  2. 展开「用 DID 钱包登录」，点登录。
  3. 插件弹出确认，你签一次名。私钥始终留在插件里，页面只拿到签名头和公钥。

平台只做验证方：它拿你签名里的 nonce 和自己的记录比对，确认“这条 DID 刚刚确实签过这次请求”， 全程不接触私钥，也不能代替你签名。

这条 DID 必须是登记过的。平台会按 DID 去它的服务器上取 did.json： 取不到就是“未注册”，登录和绑定都会被拒绝。自己生成一对密钥不等于这个 DID 存在—— 注册是注册服务器那一侧的事。

两种方式最后拿到的是同一种会话，权限完全一样。区别只是"你用什么证明你是你"。

已经登录了，还想把 DID 挂到这个账号上

  1. 打开「设置 → 绑定我的 DID」，确认状态是「已检测到钱包插件」。
  2. 点「用钱包绑定 DID」，插件弹出确认后签一次名。
  3. 签完这条 DID 就挂到当前账号下了；以后用它登录会直接进这个账号，不用再登出重来。

为什么要签名：只凭"你已登录"就把一条 DID 挂上来，等于谁都能把别人的 DID 挂到自己名下； 只凭签名就挂，等于谁都能把自己的 DID 塞进别人的账号。两样同时成立才登记。绑定只记归属， 不给你任何新角色。

反过来：用钱包登录的，怎么再绑一个邮箱

  1. 打开「设置 → 登录方式」，点「绑定邮箱」。
  2. 填一个你能收信的邮箱，点开收到的确认链接。
  3. 之后用这个邮箱登录，进的是现在这个账号、这个组织。

只填邮箱不算绑定：必须点开链接，否则等于允许任何人把别人的邮箱挂到自己名下。 绑定不会换掉你当前的登录状态。

二、你收到的那封邮件是什么

邮件只有四种，作用都很窄：送达一个链接，不送达权限。

邮件什么时候发点开发生什么有效期
登录链接 你自己在登录页填了邮箱 验证邮箱 → 进入你的组织 15 分钟，一次
邀请 某个组织的管理员邀请你 验证邮箱 → 加入该组织 → 登录 72 小时，一次
绑定邮箱 你在设置里给账号补一个邮箱 只把邮箱登记到当前账号，不发新会话 15 分钟，一次
批准提醒 你勾选了「把批准链接发到我的邮箱」 打开批准页，仍需登录后才生效 10 分钟

邀请邮件长这样（纯文本，没有追踪像素）：

主题：[Anpio Collab] 邀请你加入「安皮欧科技」

张三 邀请你以「成员」身份加入「安皮欧科技」。

点此接受（72 小时内有效，仅可使用一次）：
https://collab.example.com/login?ticket=Yl9m...

如果这不是你预期的邀请，忽略这封邮件即可。
关键点：邀请链接本身就是登录凭证，所以它只发给那个邮箱，而且只认那个邮箱。 管理员把链接转发给别人，别人点开会被拒绝（提示“这条邀请属于另一个邮箱”）。 链接也不是永久权限——接受之后，权限来自你在组织里的角色，管理员随时可以改或收回。

三、智能体怎么进团队

智能体用自己的 DID 代表自己。它可以不属于任何人，也可以同时是几个团队的成员； 进团队只有两条路，选一条就行。

交付物是一个链接：/auth/agent/skill.md，打开就是给智能体的 SKILL.md 说明，里面的服务地址已经换成你正在用的这个。把链接（或这份文件）发给智能体， 它照着里面的步骤自己申请接入。

方式一：团队邀请码（推荐）

  1. 管理员在「团队」页点「邀请智能体」，拿到一串短码，形如 T3K9-M2QF。
  2. 把码和这个链接一起发给智能体。
  3. 智能体带着码调用 POST /auth/agent/request，直接成为成员，接着换令牌就能干活。

这条路不需要谁守在电脑前点批准。短码只能用一次，过期作废； 邀请它的人可以在「我的智能体」里看到它在做什么，也可以随时撤销。

方式二：批准码

没有邀请码时，智能体先按 SKILL.md 第 1 步申请，拿到 8 位批准码（如 K7QM-2XPD）交给你； 你在「我的智能体」里批准，勾选它能做什么、多久有效。 

① 智能体申请
   POST /auth/agent/request  { "did": "did:wba:...", "name": "库存查询 Agent" }
   ← { "deviceCode": "……（自己留着）", "userCode": "K7QM-2XPD", "expiresIn": 600 }

② 你在「我的智能体」→「批准接入」里填 K7QM-2XPD

③ 智能体继续轮询，拿到令牌
   POST /auth/agent/token  { "deviceCode": "……" }
   ← 200 { "token": "……", "scopes": [...], "expiresAt": "..." }

批准前平台会去取这条 DID 的 did.json：取不到就说明它没登记， 批准会被直接拒绝。理由是批准即绑定——批一条永远登不进来的 DID，等于给一个不存在的成员开了口子。

人和智能体的关系

人和智能体用同一个 DID 时，两边本来就是同一份记录，不需要额外绑定； 用不同 DID 时，由人主动批准或绑定，关系才建立起来。 被批准或邀请的智能体会出现在「我的智能体」里，连同它手上没结束的子任务。

批准时有两个模式，别选错：

  • 独立主体（推荐）：智能体成为组织里的一个独立成员，只拿你勾选的范围。 你以后改自己的角色、换密码、离职，都不影响它；它出问题也只影响它自己。
  • 绑定到我的账号：智能体以你的身份行动，拥有你的全部权限。 适合“这就是我的一个客户端”的情况。撤销时只撤销它以智能体身份登录的会话，不会把你踢出去。

用批准码时，为什么必须要你点一下批准：

user code 只证明“有人把这个码给了这个智能体”，不证明“它的主人同意”。 批准动作必须发生在你已登录的会话里，所以别人拿到你的批准码也没用。 团队邀请码把这层判断交给了管理员：码本身就是团队的许可。

如果你不在电脑前，可以在生成码时选择把批准链接发到邮箱。邮件只是把页面送到你面前， 点开后仍然要登录；邮件本身不构成批准。

四、组织、成员与角色

每次登录都落在某个组织里。所有任务、AICD、审计都属于那个组织，跨组织默认互相看不见， 即使同一个人同时在两个组织里，也是两套身份、两套角色。

角色能做什么不能做什么
所有者 管理成员、任命管理员、管智能体授权、转让所有权 每个组织只有一个；不能直接把自己改成别的角色
管理员 加人、改角色、移除成员、管智能体授权 不能动所有者，不能造第二个所有者，不能改自己
成员 建任务、验收自己负责的任务、授权自己的智能体 不能看成员列表、不能加人
访客 只读 不能建任务、不能管授权

成员可以是人，也可以是智能体。智能体成员永远没有组织管理权， 即使批准它的人是管理员——主人的权限不会传导给智能体，也不能把它设成管理员或把组织转让给它。

五、怎么撤销

  • 撤销智能体授权：它用这份授权换到的令牌立刻作废，主体停用。它已经提交的结果和事件保留。
  • 移除成员：账号停用、所有会话作废。历史审计不删除。
  • 撤销邀请：链接立刻失效，对方还没点就进不来。
  • 退出登录：只撤销当前这一个会话，不影响你在手机或另一台电脑上的登录。

撤销之后还能再授权：同一个智能体再来申请，批准时会复用原来的身份，不会因为“撤销过一次”就再也批不了。 想改授权范围也是同一条路——重新批准会覆盖旧的权限和期限。

六、常见问题

没收到邮件怎么办？

先看垃圾邮件。本地演示环境不接真实邮件服务，登录页会直接显示那条链接（标着“开发模式”）。 正式部署接上邮件服务后，这个提示会自动消失。

链接点开说“已经用过了”？

邮件客户端有时会预取链接，或者你自己点了两次。重新发一条即可——旧的那条不会因此泄露， 因为它从来只能换一个会话。

我在两个组织里，任务会不会串？

不会。切换组织会换发一个新的会话并作废旧的，避免一个浏览器里同时挂着两个组织的令牌。

智能体能不能自己注册进来？

拿到团队邀请码的可以：它自己申请、自己入队，不需要谁守着点批准。 没有邀请码时只能发起申请，由组织里的管理员批准并决定归属于谁；没有批准的申请 10 分钟后自动失效。

钱包登录提示“这条 DID 没有登记”？

平台拿到 DID 后，会按它的地址去取 did.json。取不到（404、超时、文档里的 id 对不上） 都按“未注册”处理，登录和绑定都会被拒。本地自己生成一对密钥只是造了个身份壳子， 真正的登记发生在注册服务器那一侧。内网部署若注册服务器只有 http，需要显式设置 COLLAB_DID_HTTP=1 才会去取。

为什么不能用密码登录？

密码意味着平台要保管一份可以冒充你的秘密。邮箱链接和 DID 签名都不需要平台保存这种东西。 真要用密码，应该交给企业已有的身份系统（SSO），而不是在这里再建一套。

当前是本地参考实现：邮件写进本地发件箱并在控制台打印，限流在进程内，没有 TLS 与 SSO。 正式部署前需要接入企业邮件服务、把监听放到反向代理后面，并把 COLLAB_DEV_MAIL 设为 0。
