# Anpio Collab

企业智能体协作平台的本地原型。总体目标和阶段见 [plan.md](plan.md)。本仓库当前实现 TypeScript 本机 HTTP 协作流程；它不是可用于企业部署的产品。

## 运行 TypeScript 原型

需要 Node.js 24 或更新版本，使用 Node 自带的 TypeScript 类型剥离和 SQLite，无需安装依赖。首次启动时在自己的终端设置强随机令牌（不要将令牌放入代码或 Git）：

```sh
export COLLAB_BOOTSTRAP_TOKEN="$(openssl rand -hex 32)"
npm start
```

浏览器打开 `http://127.0.0.1:8787/` 使用本地管理台，在页面中输入访问令牌。服务只监听 `127.0.0.1:8787`；`PORT` 可调整端口，`COLLAB_DB` 可指定 SQLite 文件。首次启动创建 `admin` 主体及 `local` 工作空间，之后数据库中主体已存在时不会重置令牌。服务重启后使用相同数据库即可恢复状态。

```sh
npm test
npm run demo
```

测试和演示需要能够绑定本机回环端口。演示在临时数据库上启动 HTTP 服务，让库存和供应商示例 Agent 各自作为独立进程接收和提交任务，然后进行模拟人工验收、经验审核发布，并由第二个任务引用经验；运行结束后删除临时数据。`demo` 中的验收由脚本模拟，实际人员可通过接口进行验收。接口、角色和 Agent 集成方式见 [协议说明](docs/protocol-v1.md)，本地备份及恢复边界见 [运行说明](docs/local-operations.md)。

## 实现范围和限制

- 已实现工作空间主体、令牌停用、任务及子任务状态、事件、事务内幂等、基础访问审计、负责人验收/退回、人工标记超时、候选经验审核/发布/撤销、有效知识查询和历史版本引用。客户端及示例 Agent 通过 HTTP 通信而非共享数据库。
- 每个请求重新验证令牌，受派 Agent 只能读取自己的任务和子任务；知识可由审核人按主体或工作空间授权，默认不向普通主体共享。旧数据维持原有范围，须主动审查。撤权不会自动删除已经复制到任务结果或摘要中的内容，提交者必须遵守数据共享范围。
- SQLite、本地共享令牌、单机服务及模拟数据只供开发验证。本地审计不能防篡改或保证完整性。没有企业身份、DID、ANP 消息、生产密钥管理、PostgreSQL/pgvector、真实业务系统、证据原件鉴权、自动超时调度、平台持久消息队列或索引服务。提供本地管理台及供用户 Agent 调用的通用命令行桥接，但 Claude Code 或 Codex 专用适配尚未验证。示例不证明企业或跨组织隔离。
- 规则型协调 Agent 作为独立进程运行，负责人需明确委派；它可分派和汇总，不能验收。示例业务 Agent 使用 `COLLAB_WORKER_DB` 指定本地 SQLite 日志，保存未确认的请求并在重启后重放；每个 Agent 应使用独立且受保护的文件，不能并发运行同一日志。遇到撤权或状态冲突时停止并由负责人核对，不自动重试业务操作。知识支持修订、重新审核和历史版本留存；尚无检索评测。
- 根目录 `collab/`、`agents/` 和 `examples/demo.py` 是早期 Python 原型，保留用于对照；与 TypeScript 数据库和接口互不兼容，不会自动迁移旧数据。
